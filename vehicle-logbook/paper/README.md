# Паперовий логбук — перехідний період

Телефон як трекер виявився ненадійним: Samsung Galaxy S22 Ultra (SM-S908W)
душить фоновий GPS. За 22.09 Traccar Client мав віддати 5760 позицій,
віддав 970 — 83% замірів не сталися. Це не мережа: середня затримка
доставки 1.4 с, максимум 105 с за добу. Точки не приходили пізно — їх
просто не робили.

Поки не приїде апаратний трекер (Teltonika FMM003), первинним записом
стає папір. CRA приймає паперовий журнал без застережень; зшита книга з
послідовними сторінками виглядає надійніше за експорт із бази.

## Перегенерувати

```sh
pip install reportlab
python3 make-logbook.py trips-2026-09-16_22.csv logbook-pacifica-2026.pdf
```

Свіже вивантаження з бази (LXC 415):

```sql
SELECT to_char(started_at AT TIME ZONE 'America/Moncton','YYYY-MM-DD') AS d,
       origin_address, destination_address, distance_km, classification,
       coalesce(purpose,'') AS p
  FROM fleet.trips ORDER BY started_at;
```

Роздільник `|`, бо в адресах і меті трапляються коми.

## Колонки

Перші чотири (дата, пункт призначення, мета, кілометраж) — те, що CRA
вимагає буквально. Одометр per-trip не вимагається, але робить книгу
самоперевірною: фініш одного рядка має збігтися зі стартом наступного.
Розходження одразу видно, і його видно й аудитору — тому колонку краще
заповнювати, ніж лишати порожньою.

## Що не забути

Одометр на кінець податкового року — обовʼязковий, без нього journal
неповний незалежно від якості записів по поїздках.
